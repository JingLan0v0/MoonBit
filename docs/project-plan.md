## 2. 赛道比较与选择理由

官网提供以下四个方向作为选题参考，并非封闭、互斥的强制赛道。下表是本项目的判断，不是官方难度评级。

| 官网方向 | 可以做的项目 | 针对本次目标的判断 |
| --- | --- | --- |
| 工具库 | 编解码、配置解析、通用组件 | 易控制范围，但单个简单函数库可能难以体现完整使用场景 |
| 数据处理 | 表格比较、日志分析、格式处理 | 输入输出可固定，正确性容易验证，可同时交付库和实际工具；选择此方向 |
| AI 应用 | 文档问答、智能助理 | 容易受密钥、额度、网络和模型输出波动影响，不作为本期方案 |
| 开发者工具 | CLI、解释器、LSP | CLI 本身可控，但解释器和 LSP 范围较大；本项目只借用 CLI 作为交互方式 |

选择 MoonRow 的原因：数据比较是真实需求；不需要后台服务或付费资源；算法可拆成独立可测模块；测试能覆盖失败场景；无需美术资源和复杂界面；完成后既能直接运行，也能让其他 MoonBit 项目复用。

这不是“发明此前不存在的 CSV 比较算法”的项目。其他语言已有成熟同类工具，技术风险因此较低。2026-09-21 的初步检索发现 MoonBit 生态已有 CSV/JSONL 数据质量工具 MoonVerity，因此本项目聚焦“两份数据快照的差异比较”，不扩展成另一套数据契约验证平台。检索不是完整查重，也不构成生态首创证明。开工与申报前还需按最终名称和功能再核对同类项目。

## 3. 产品定义

### 3.1 一句话介绍

MoonRow 是用 MoonBit 实现的离线 CSV 差异比较工具：给定旧表、新表和标识记录的列，输出新增、删除、修改与未变化的数量，并列出具体字段的前后值。

### 3.2 使用者与场景

1. 开发者比较两次数据库导出，确认哪些记录发生了变化。
2. 运营人员比较两批商品目录，发现商品新增、下架、名称或价格文本变化。
3. 数据处理流程比较基准结果与新结果，以退出码让自动检查判断是否出现差异。

所有演示使用自制虚构数据，不依赖真实客户、订单或个人信息。这里只做数据差异识别，不做金额审计或支付结算。

### 3.3 最小完整交付形态

- 一个可复用的 MoonBit 包，包含 CSV 解析、表结构校验、主键匹配和差异结果模型。
- 一个调用同一核心库的命令行入口。
- 三种报告：终端文本、JSON、Markdown。
- 一套固定输入、预期结果和可重复执行的测试。
- 安装运行文档、接口说明、限制说明、开源许可证和验收演示。

### 4.2 明确不纳入本期

不做 Excel 原生文件读写、JSON 输入、自动识别编码、GBK 转码、数据库连接、图形界面、网页上传、云端存储、登录、AI 摘要、模糊匹配、数值容差、自动修复、应用补丁、超大文件流式比较和完整 CSV 方言支持。

### 4.3 必须锁定的行为

1. 输入必须有表头；空文件、空表头名、重复表头名报错。表头精确区分大小写，不自动去空格。
2. 只有表头、没有数据行是合法空表。空物理行按 CSV 记录规则解析，不自动略过；解析出的字段数仍须匹配表头。末尾一个记录终止符不额外制造空记录。
3. 支持 LF 和 CRLF 作为记录分隔，拒绝引号外孤立 CR；引号内保留原始换行字符。未加引号字段出现双引号、引号未闭合、闭引号后出现非分隔字符均报错。
4. 双引号字段内用两个双引号表达一个字面双引号。中文、emoji 和逗号在合法引号字段中能正常保留。按项目文档规定的 CSV 子集实现，不声称完整覆盖所有 CSV 工具行为。
5. 两表列顺序可以不同；去除显式忽略列后，列名集合必须一致，否则报结构错误。忽略列必须至少在一侧存在，避免拼写错误被默默接受；允许被忽略列只出现在一侧。主键列必须在两侧存在且不得忽略。
6. 至少保留一个非主键比较列，避免把错误配置误当成有效比较。每个主键列只能声明一次。
7. 主键的每个组成字段均不能是空字符串；只含空格是非空原始字符串。重复主键直接失败，指出同侧冲突记录，不能用后一条覆盖前一条。
8. 组合主键必须使用无歧义的编码或结构类型，不能简单用逗号、竖线拼接。测试必须覆盖 `['a|b','c']` 与 `['a','b|c']` 等碰撞样例。
9. 单元格默认原样比较：`001` 与 `1` 不同，`1.0` 与 `1.00` 不同，空格、大小写和换行形式均保留。不推断数字、日期或空值类型。
10. 行重排、列重排不会单独构成差异。主键值变化表现为删除旧记录、新增新记录。
11. `changed` 统计记录数，`changed_cells` 统计变更字段数，两者不能混淆。忽略列不进入变更统计或报告数据。
12. 差异列表按主键组成字符串逐项排序，字段按列名排序；采用明确的非本地化字符串序，不能依赖哈希表遍历顺序。验证相同数据不同输入顺序得到相同语义报告。
13. 文件读取使用严格 UTF-8 解码，非法字节应报错，不能用替换字符悄悄修复。位置至少提供数据记录编号；解析语法错误另给物理行/列。引号内换行时，这两套编号要区分。
14. 本期按内存内处理实现。拟设置每个输入文件最多 10 MiB、最多 50,000 条数据记录、最多 100 列、单字段最多 256 Ki 个 UTF-16 代码单元。超过任一限制明确失败；阈值需在开工后验证并锁定，写入 README，不宣称无限规模。
15. 读取前检查文件大小，读取后再次检查实际字节数；解析时检查行数、列数与字段长度。不得先生成无限中间结果再检查限制。

## 5. 技术方案

### 5.1 实现分工

使用 MoonBit 实现解析器、数据模型、校验、索引、比较、排序、参数解释和报告格式化。Node.js 仅提供宿主所需的参数获取、文件字节读取、严格 UTF-8 解码、标准输出和进程退出能力，通过少量 FFI 接入。

采用 MoonBit 编译到 JavaScript 的路线，以降低 Windows 原生编译和操作系统适配的额外工作。该路线有官方文档支持，但本项目还没有做编译验证。开工第一步必须验证最小调用链，再冻结工具链版本和构建方式。

核心包尽量只依赖 MoonBit 标准库。不能在 JavaScript/Python 中完成 CSV 解析与比较后，仅用 MoonBit 包装调用。生成的 JavaScript 与手写宿主适配代码要分开说明。

### 5.2 模块划分与处理流程

处理顺序：参数校验 → 读取与解码 → CSV 解析 → 表结构与主键校验 → 建立索引 → 计算差异 → 排序 → 生成报告 → 返回退出码。

| 模块 | 职责 | 测试重点 |
| --- | --- | --- |
| `csv` | 状态机解析、位置跟踪、资源限制 | 引号、换行、BOM、空字段、非法输入 |
| `table` | 表头映射、忽略列、主键检查 | 重复列、缺列、组合键、空键、重复键 |
| `diff` | 匹配两表，生成结构化差异 | 新增/删除/修改、行列重排、计数不变量 |
| `report` | text/json/markdown 渲染 | 一致性、转义、排序、原始值保真 |
| `cli` | 纯参数解析、任务调度、退出语义 | 缺参、未知参数、错误分流 |
| `cmd/main` | 调用宿主 I/O 和执行 CLI | UTF-8、路径、标准流、真实进程退出码 |

CSV 解析器按“字段起始、未加引号、引号内部、闭引号后”等状态处理。索引使用可验证的无歧义主键，不使用有碰撞风险的简易字符串连接。预期核心复杂度为输入字节线性解析，加基于索引的记录比较；报告排序额外需要排序成本。性能数字必须实测后记录，不预先写成成绩。

### 5.3 核心数据与接口约定

以下是逻辑接口，不是保证当前编译器可以原样编译的语法：

- `parse_csv(text, limits) -> Result<Table, CsvError>`
- `validate_tables(before, after, options) -> Result<PreparedTables, ValidationError>`
- `compare(prepared) -> DiffResult`
- `render(result, format) -> String`
- `parse_args(args) -> Result<Command, UsageError>`

`Table` 至少保留表头、原始字符串行和记录位置。`DiffOptions` 包含主键列和忽略列。`DiffResult` 包含 `schema_version`、主键列、比较列、摘要、新增记录、删除记录和修改记录。错误应有稳定错误码、说明、输入侧别及适用的位置字段。

JSON 报告版本初始拟为 `1`；摘要包含 `before_rows`、`after_rows`、`added`、`removed`、`changed`、`unchanged`、`changed_cells`、`has_diff`。新增/删除项目含主键与未忽略列的字段值，修改项目含主键和逐字段的 `before`/`after`。单元格值始终序列化为字符串。

必须成立的计数关系：

- `before_rows = removed + changed + unchanged`
- `after_rows = added + changed + unchanged`
- `has_diff = (added + removed + changed > 0)`

### 5.4 预期命令行体验

最终用户入口拟名 `moonrow`。以下是目标用法，不是当前已有命令：

```text
moonrow before.csv after.csv --key sku
moonrow before.csv after.csv --key sku --key warehouse --ignore updated_at
moonrow before.csv after.csv --key sku --format json
moonrow before.csv after.csv --key sku --format markdown
moonrow --help
moonrow --version
```

重复使用 `--key` 和 `--ignore` 表达多列，不把逗号列表作为第一版语法。文件路径支持空格和中文。报告写标准输出，错误写标准错误；不提供直接覆盖文件的 `--output` 功能，由使用者自行重定向。

| 退出码 | 含义 |
| --- | --- |
| 0 | 比较成功且没有差异；或者帮助/版本请求成功 |
| 1 | 比较成功且存在差异 |
| 2 | 参数、输入格式、结构、资源限制或 I/O 错误 |

实际进程测试须直接启动编译产物，验证退出码是否被工具链包装改变。JSON 模式标准输出只包含一个完整 JSON 值，不混入构建日志；失败时标准输出为空，错误信息走标准错误。错误显示需转义终端控制字符；Markdown 特殊字符和原始 HTML 需安全转义，不能把输入值当作可执行内容。

## 6. 固定演示与验收用例

### 6.1 五分钟演示的主样例

旧文件：

```csv
sku,name,price,updated_at
A001,苹果,3.00,2026-09-20
A002,香蕉,4.00,2026-09-20
A003,梨,5.00,2026-09-20
A005,葡萄,8.00,2026-09-20
```

新文件故意改变记录顺序：

```csv
sku,name,price,updated_at
A005,葡萄,8.00,2026-09-21
A003,梨,5.00,2026-09-21
A001,苹果,3.50,2026-09-21
A004,橙子,6.00,2026-09-21
```

指定 `--key sku --ignore updated_at` 后，预期：新增 A004；删除 A002；修改 A001 的 price，从字符串 `3.00` 到 `3.50`；A003、A005 未变化。

摘要必须为：旧表 4 行、新表 4 行、新增 1、删除 1、修改 1、未变化 2、变更字段 1；退出码 1。三种报告均需体现同一结果。

### 6.2 必测矩阵

| 类别 | 需要证明的行为 |
| --- | --- |
| 基本正确性 | 相同表为零差异；全新增；全删除；混合变化；单行多字段变化 |
| 顺序无关 | 行重排、列重排不制造变化；结果顺序不随输入变化 |
| 主键 | 单列、多列、空键、重复键、键列缺失、组合键分隔符碰撞 |
| CSV | 引号中的逗号、双引号、换行；LF/CRLF；BOM；中文与 emoji；末尾换行 |
| 非法 CSV | 未闭合引号、非引号字段中的引号、引号闭合后垃圾字符、列数不一致 |
| 表结构 | 空文件、仅表头、空表头、重复表头、不一致列、忽略列的单侧存在 |
| 原始值 | `001`/`1`、空字符串、前后空格、大小写、换行形式都不被隐式转换 |
| 报告 | JSON 可解析且值完整；Markdown 的竖线、换行、反引号与 HTML 转义；终端控制字符转义 |
| CLI | 缺少 key、未知参数、参数缺值、找不到文件、中文/空格路径、UTF-8 错误 |
| 退出码 | 编译产物实际返回 0/1/2，标准输出与标准错误正确分流 |
| 资源限制 | 对每项阈值测试低于、等于、超过；错误可解释，不崩溃或静默截断 |
| 库复用 | 独立小示例导入公共包并完成比较，防止只有 CLI 能用 |

此外用固定种子的生成样例验证：与自身比较无差异；打乱顺序结果不变；交换两表后新增/删除互换且修改前后值互换；摘要满足上述计数等式。可在测试脚本中用简单独立实现校验受限样例，但产品不能依赖该脚本。

测试数量不是官方门槛，也不能用大量重复断言代替覆盖。以上类别必须有实际证据。性能测试采用自制 10,000 行样例，记录环境、耗时和结果一致性；再验证已声明上限，不能只凭复杂度推导声称通过。

## 10. 一页申报说明的内容草稿

本节是后续制作一页说明的素材，尚未填入身份和公开仓库链接，尚未导出 PDF、尚未提交。实际格式以报名表为准。

**项目名称：** MoonRow——MoonBit CSV 主键差异比较库与命令行工具。

**参赛方向：** 数据处理。**项目性质：** 全新开源项目，拟采用 Apache-2.0。

**问题与价值：** 两次商品目录或数据库导出即使只改变记录顺序，普通逐行文本比较也可能产生大量噪声。MoonRow 按业务主键对应记录，输出新增、删除、修改及字段前后值，帮助开发者复核数据变更。

**拟实现内容：** 用 MoonBit 实现 CSV 解析、表结构检查、单列及组合主键匹配、忽略指定非主键列、确定顺序的差异结果、文本/JSON/Markdown 报告。提供可复用包和命令行入口，正确区分无差异、有差异和输入错误。

**范围：** UTF-8 CSV，离线运行，精确字符串比较；首版不做数据库、网页、Excel 原生格式和智能推断。Node.js 只负责宿主 I/O。

**验收方式：** 固定商品数据样例验证一增一删一改两条不变；测试覆盖 CSV 转义、组合键碰撞、重复键、结构错误、行列重排和真实进程退出码。提供 Windows 复现记录与 Linux CI。

**交付：** 公开仓库、连续开发记录、MoonBit 核心库和 CLI、README、示例、测试、许可证、固定版本及可复现演示说明。

**计划：** 获得开工授权后尽早申报，目标 2026-09-28 准备好验收材料，并在官方确认的截止时间前提交。

**待填写：** 参赛者姓名/队伍、GitHub ID、联系信息、公开仓库 URL、实际起止日期。不要自行补造。
